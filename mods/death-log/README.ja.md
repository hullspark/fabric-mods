# Death Log（死亡記録）

死ぬたびに「いつ・どこで・どんな死亡メッセージだったか」（例:「Steve was
slain by Zombie」）を記録し、`/deathlog` コマンドで直近の死亡履歴を振り
返れる小さな Fabric MOD。墓標もテレポートもミニマップも無く、読める履歴
だけを残す。

**AI 支援開発の開示**: 本 MOD のコードは AI（Claude）の支援を受けて書か
れています。他の MOD のコードやアセットは流用していません。

## 機能

- バニラの死亡イベントをサーバー側で監視し、死ぬたびにそのプレイヤーの
  履歴へ1件追加する。記録内容は実時刻（壁時計時刻）・ディメンション・
  死亡地点の座標・死亡メッセージ文字列（**サーバー側の言語**で解決した
  もの。専用サーバーでは通常は英語固定、シングルプレイではその瞬間の
  クライアント言語）。これは各プレイヤー自身のクライアントのチャットに
  実際に表示される言語とは限らない。詳細は下記の「既知の制限」を参照。
- `/deathlog` で自分の直近の死亡（最大10件）を新しい順に番号付きで表示
  する。表示例:
  ```
  #1  2026-09-30 12:34 UTC  the_nether (12, 40, -8)  — Steve was pricked to death by a Cactus
  ```
  時刻表示は常に UTC 固定（サーバーのローカルタイムゾーンに関係なく）な
  ので、誰が見ても同じ表記になる。
- 各プレイヤーの履歴は直近20件まで保持し、それより古いものは自動的に消
  える。
- 履歴はワールド/サーバーごとに、そのワールドのセーブフォルダ内の
  `deathlog.json` に保存される。ワールドをコピー・バックアップ・削除す
  れば死亡記録もそれに従う。ファイルが無い・壊れている場合は空の履歴と
  して扱いクラッシュしない。書き込みに失敗した場合はログに警告を出し、
  そのセッション中はメモリ上のみで動作を継続する。
- サーバーがバニラの死亡メッセージ・死亡画面のために既に計算している情
  報を読むだけで、自動操作は一切行わず、サーバーが不正と見なしうる挙動
  もしない。

## どちら側で記録されるか

死亡はバニラの死亡メッセージ自体と同じくサーバー側の権威データである:

- **シングルプレイ**: 統合サーバーがクライアントと同一プロセスで動くた
  め、MOD を入れるだけでそのまま機能する。
- **専用マルチプレイサーバー**: **サーバー側**に導入する。`/deathlog`
  は通常のサーバーコマンドのため、そもそもサーバー側に MOD が入ってい
  る必要がある（プレイヤー側の導入は必須ではない）。

## 既知の制限

- **死亡メッセージは「サーバー側の言語」で記録される（各プレイヤー自身
  の言語ではない）。** バニラは通常、死亡メッセージを未翻訳のキーのまま
  送り、各クライアントが自分の言語でチャットに表示する。本 MOD はサーバ
  ー側で一度だけプレーンテキストに解決してから保存するため、`/deathlog`
  は誰が実行しても・どのクライアント言語でも常に同じ1つの言語（専用サー
  バーでは通常英語）で表示される。サーバー側に翻訳が登録されていない他
  MOD 由来のダメージ種別による死亡は、`death.attack.foo` のような生の翻
  訳キーのまま表示される。

### 実機で未検証

本 MOD はディスプレイの無いコンテナ内でビルド・検証した。`./gradlew
build`（後述の単体テストを含む）は成功し、ヘッドレスの専用サーバー
（`./gradlew runServer`）・ヘッドレスクライアント（Xvfb 上の
`./gradlew runClient`）とも起動時エラー無しを確認した。`/deathlog` は
サーバーコンソール（プレイヤーではない実行者）から実行すると「プレイヤ
ーのみ使用可」の応答を返すところまでコマンド登録自体は確認できた。一方
で、**実際にプレイヤーが死んで `/deathlog` を実行する一連の流れ**は、
この環境に接続できるプレイヤーがいないため検証できていない。具体的に未
検証なもの:

- 実際のチャット画面での `/deathlog` の表示（折り返し・色）。
- 記録した死亡メッセージが、あらゆる死因（攻撃者なし・落下・溺死・火
  など）でバニラの死亡画面/チャットの文言と一致すること。
- 複数プレイヤーでの同時使用、および死亡と死亡の間でのサーバー再起動/
  クラッシュ（永続化ロジック自体は実際の一時ディレクトリに対する単体テ
  ストで確認済み — 再読み込みで履歴が残ること、上限を超えたときに古い
  ものから消えること、壊れた/存在しないファイルからの復旧を含む — が、
  実際のサーバープロセスがセッション途中で再起動するケースは未検証）。

Minecraft 1.21.11 向け。Fabric Loader と Fabric API が必要。
